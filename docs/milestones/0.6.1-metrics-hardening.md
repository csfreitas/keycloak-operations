# Milestone 0.6.1 — Metrics Hardening & Documentation Cleanup

## Status

**COMPLETED**

| | |
|--|--|
| Version | `0.6.1-SNAPSHOT` |
| Builds on | 0.6 (`59461d1`) |

## Objective

Harden the 0.6 metrics stack: enforce query bounds, temporal DB awaiting analysis, complete PerformancePolicy usage, accurate histogram/stale availability, stronger isolation, ServiceMonitor/scrape readiness, Kubernetes deploy/RBAC cleanup, and documentation consistency — without changing the overall architecture.

## Requirements

- FR-METRICS-001 … FR-METRICS-006
- NFR-BOUND-001, NFR-RES-001, NFR-RES-002, NFR-ISO-001, NFR-TSDB-001
- SEC-METRICS-001 … SEC-METRICS-003, SEC-MULTI-001, SEC-CRED-001, SEC-INFRA-002
- COMPAT-005, COMPAT-006
- ADR [0005](../adr/0005-postgresql-is-not-a-tsdb.md), [0006](../adr/0006-semantic-metrics-instead-of-raw-promql.md)

## Scope

- Enforce `metrics.max-range` / `max-series` / `max-points` / `stale-after`
- `query_range` for Agroal awaiting (current / average / max)
- Wire unused PerformanceConfig: p95, db critical, GC pause
- Rules: KC-PERF-HTTP-P95-001, KC-PERF-DB-002, KC-PERF-GC-001, KC-PERF-CLUSTER-001
- Histogram presence via bucket series count; NO_TRAFFIC vs histogram missing
- STALE detection; stale metrics do not drive PASS findings
- Mandatory target discriminators (namespace alone insufficient)
- Credential + same-namespace multi-target isolation tests
- Lab A/B Prometheus bindings; smoke isolation check
- ServiceMonitor probe + scrape readiness evidence
- Kubernetes RBAC/ports/image alignment with OpenShift model
- Documentation cleanup (ports, AGENTS, project-state, metrics catalog)

## Architecture Impact

No new architecture. Extends MetricsProvider (`probeSeries`, `queryRange`), evidence keys, and deploy manifests.

## Security

- PromQL injection regressions expanded
- No Secret list/get in Kubernetes assessor Role
- ServiceMonitor list is optional; permission denied → PARTIAL/UNKNOWN, not hard fail

## Testing

Unit coverage for bounds, isolation, credentials, evidence SLO/GC/critical/stale/no-traffic, RBAC manifest guardrail. Failsafe ITs remain opt-in.

## Acceptance Criteria

See project checklist in the implementation PR / verification section of `project-state.md`. Core items: bounds enforced, policies effective, histogram/no-traffic/stale correct, isolation tests, ServiceMonitor/scrape evidence, K8s hardening, docs, `mvn clean verify` green, no Web UI.

## Known Limitations

- Live Prometheus/Keycloak/RHBK ITs still opt-in
- ServiceMonitor discovery requires monitoring.coreos.com API + RBAC
- VM inventory still future

## Out of Scope

Web UI, Grafana, Tempo, alerts, ML, Keycloak writes, raw PromQL tools (0.7+)
