## Objective

Integrate target-bound telemetry (Prometheus / Thanos / OpenShift Monitoring) as semantic metrics and assessment evidence — without raw PromQL or arbitrary endpoints from clients.

## Requirements

- FR-METRICS-001 … FR-METRICS-006
- FR-ASSESS-001, FR-ASSESS-005
- SEC-METRICS-001 … SEC-METRICS-003
- SEC-TARGET-001, SEC-CRED-001, SEC-MULTI-001
- NFR-RES-001, NFR-RES-002, NFR-BOUND-001, NFR-TSDB-001
- ADR [0005](../adr/0005-postgresql-is-not-a-tsdb.md), [0006](../adr/0006-semantic-metrics-instead-of-raw-promql.md)

## Scope

Delivered in `59461d1` (verified against code/CHANGELOG):

- Metrics providers: Prometheus, Thanos (compatible path), OpenShift Monitoring, NONE
- Target-aware endpoint / credential / selector resolution
- Semantic metrics (HTTP, Agroal/DB pool, JVM, cache, cluster, auth events when available, runtime CPU/memory)
- Controlled windows; histogram-gated percentiles; availability (never fake zeros)
- Performance summary + metrics evidence + performance rule pack / profiles
- Configurable performance thresholds (no universal mandatory SLO)
- Semantic MCP tools and REST metrics APIs
- PromQL escaping / injection resistance; multi-target metrics isolation
- Lab Prometheus compose + smoke script
- PostgreSQL stores derived evidence/findings only — not continuous samples

## Architecture Changes

```text
Keycloak/metrics → Prometheus/Thanos/OCP Monitoring → MetricsProvider → MetricsService
  → REST / MCP / MetricsEvidenceCollector → Assessment Engine
```

Details: [`../architecture/observability.md`](../architecture/observability.md).

## Main Capabilities

| Capability | Notes |
|------------|--------|
| Semantic metrics by category | HTTP, DATABASE, JVM, CACHE, AUTHENTICATION, CLUSTER, RUNTIME |
| Performance summary | Aggregated DTO, not raw Prometheus payload |
| Performance assessment | Rules + optional SLO config |
| Graceful degradation | Static assessment continues without metrics |

## MCP Changes

- `keycloak_get_metrics_status`
- `keycloak_get_performance_summary`
- `keycloak_get_metrics` (category + window enums)
- No raw PromQL tools

## REST Changes

- `/api/v1/targets/{targetId}/metrics/status|summary|http|database|jvm|cache|authentication|runtime|cluster`

## Persistence Changes

- No TSDB samples in PostgreSQL
- Target observability binding / assessment evidence as derived data only

## Security Considerations

- SEC-METRICS-*; mandatory selectors; TLS defaults retained; credential isolation

## Testing

Unit coverage for query builder, escaper, API client, evidence, isolation; opt-in `PrometheusMetricsIT`.

## Acceptance Criteria

- [x] Target-aware Prometheus / OpenShift Monitoring paths
- [x] No arbitrary metrics URL / raw PromQL from clients
- [x] Semantic MCP + REST
- [x] Percentiles only with histograms
- [x] Performance summary + evidence + rules
- [x] Metrics failure does not block static assessment
- [x] Isolation / injection-oriented tests present

## Known Limitations

- Live Prometheus/Keycloak/RHBK ITs opt-in
- Observability binding required for runtime metrics
- ServiceMonitor scrape-state coverage may need deeper env validation

## Out of Scope

- Web UI, Grafana embedding, Alertmanager, Tempo, ML, capacity prediction, raw PromQL
