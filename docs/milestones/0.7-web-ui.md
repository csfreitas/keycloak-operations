## Objective

Provide a browser console for fleet operations that consumes **only** the backend REST/SSE API.

## Requirements

- FR-UI-001, FR-UI-002
- FR-REST-001, FR-MCP-001 (backend remains shared services)
- SEC-CRED-002, SEC-TARGET-001, SEC-MULTI-001
- ADR [0004](../adr/0004-no-arbitrary-endpoints-from-mcp.md) applied to the browser as well

## Scope

Planned product surfaces:

- Fleet dashboard (targets, product, environment, version, runtime, health, score, critical/high findings)
- Target overview (version, runtime, namespace, pods, zones, health, assessment, performance summary)
- Health, assessment, findings
- Performance (semantic metrics via backend)
- Infrastructure (inventory via backend)
- History (assessments, health, snapshots, audit)
- OIDC authentication + backend authorization
- SSE for operational events (beyond current heartbeat stub)

## Architecture Changes

```text
Browser → REST / SSE → Operations Backend → PostgreSQL / Keycloak / OCP / Prometheus
```

The browser **MUST NOT** access Keycloak Admin, OpenShift/Kubernetes APIs, Prometheus, or PostgreSQL directly.

Prefer a separate UI module/repository unless productization requires otherwise. See [`../ui-architecture.md`](../ui-architecture.md).

## Main Capabilities

Presentation and aggregation over existing `/api/v1` capabilities; no duplicated Keycloak/infra/metrics logic in the browser.

## MCP Changes

None required (MCP remains for agents).

## REST Changes

Reuse existing APIs first; may add UI-oriented aggregations or richer SSE event types.

## Persistence Changes

None for the UI itself.

## Security Considerations

- No backend system credentials in the browser
- OIDC + target authorization
- No secrets in frontend bundles

## Testing

- UI component/contract tests (when module exists)
- Backend `mvn clean verify` remains green
- Authorization / target isolation regression
