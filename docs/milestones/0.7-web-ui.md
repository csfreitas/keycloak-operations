# Milestone 0.7 — Web UI / Fleet Operations Console

## Status

**COMPLETED**

| | |
|--|--|
| Version | `0.7.0-SNAPSHOT` |
| Evidence | `ui/` React console; enriched fleet/overview REST; health/snapshot detail; SSE operational events; optional `%oidc`; OpenShift UI manifests |

## Objective

Provide a browser console for fleet operations that consumes **only** the backend REST/SSE API.

## Requirements

- FR-UI-001, FR-UI-002
- FR-REST-001, FR-MCP-001 (backend remains shared services)
- SEC-CRED-002, SEC-TARGET-001, SEC-MULTI-001
- ADR [0004](../adr/0004-no-arbitrary-endpoints-from-mcp.md) applied to the browser as well

## Scope

Product surfaces delivered:

- Fleet dashboard (persisted overview — no N+1 live checks)
- Target overview
- Health, assessment, findings
- Performance (semantic metrics via backend)
- Infrastructure (inventory / snapshot via backend)
- History (assessments, health, snapshots, audit)
- Optional Identity A OIDC (`%oidc` profile); OPEN_LAB default
- SSE for operational events (assessment/health completed + heartbeat)

## Architecture Changes

```text
Browser → REST / SSE → Operations Backend → PostgreSQL / Keycloak / OCP / Prometheus
```

The browser **MUST NOT** access Keycloak Admin, OpenShift/Kubernetes APIs, Prometheus, or PostgreSQL directly.

Frontend lives in-repo as `ui/` (React + TypeScript + Vite). Production assets are served via a separate nginx image — not embedded in the Quarkus JAR. See [`../ui-architecture.md`](../ui-architecture.md) and [`../../ui/README.md`](../../ui/README.md).

## Main Capabilities

Presentation and aggregation over `/api/v1`; no duplicated Keycloak/infra/metrics logic in the browser.

## MCP Changes

None (MCP remains for agents).

## REST Changes

- Enriched `GET /api/v1/fleet` and `GET /api/v1/targets/{id}/overview`
- `GET .../health-checks/latest|{id}` (components)
- `GET .../snapshots/latest|{id}` (summary payload)
- `GET /api/v1/me`
- SSE `GET /api/v1/events` (JSON operational events)
- CORS for local UI origins

## Persistence Changes

None for the UI itself.

## Security Considerations

- No backend system credentials in the browser
- UI OpenShift Deployment: `automountServiceAccountToken: false`, no assessor SA
- Secrets filtered by existing `SensitiveDataFilter`
- OIDC optional via `%oidc`

## Testing

- UI Vitest component/route tests (`cd ui && npm run test:run`)
- Backend `mvn clean verify`
- UI deploy RBAC guardrail test

## Acceptance Criteria

- [x] Fleet, overview, health, assessment, findings, performance, infrastructure, history views
- [x] REST/SSE-only browser access
- [x] OIDC-ready backend authz + OPEN_LAB default; frontend auth module
- [x] Documentation updated

## Known Limitations

- Multi-replica SSE fan-out not implemented (in-process bus)
- Full interactive OIDC login UX requires operator IdP client configuration
- Browser smoke against live compose is operator/local validation

## Out of Scope

- Grafana embedding, direct PromQL, controlled Keycloak writes, replacing MCP
