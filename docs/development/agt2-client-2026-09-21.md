## Implemented and reviewed boundaries

- Independent profile/answer **0.1.0**; existing observation schema **1.0**.
- Fresh authorized catalogue, explicit scope selection and at most three sequential
  reads through exactly two fixed tools. No auto-selection, fuzzy resolution or
  privileged report/legacy fallback; one unavailable/forbidden read rejects the answer.
- Closed typed observations, source/scope/UUID binding, missing/null semantics,
  product version UNKNOWN and exact observation-local fact references. No assessment,
  health verdict, rating or natural-language inference is fabricated.
- Whole-question time/call/concurrency budgets, per-response/total/output bytes,
  JSON depth/duplicate keys, freshness and conflicting text/structured-content checks.
- Trusted context-generation binding; invalidation before dispatch/during reads,
  late-error rejection, local output-expiry checks and immutable results. A transport
  that ignores cancellation blocks subsequent work until it settles.
- Synthetic two-persona CLI with fixed diagnostics; no network, credentials, model,
  arbitrary file/command access, conversation persistence or resource creation.

The proportional security review traced request → catalogue → scoped read → output
and checked actor/client/context ownership, malicious metadata, error disclosure and
resource exhaustion. It added regressions for array/object kind values that JavaScript
could otherwise coerce into field-map keys, and for non-cooperative cancellation.
This was a local implementation review, not independent security certification.
All requests and evidence remain untrusted data; the host callbacks/executable
JavaScript are trusted. No free-form prompt is used as access control.
