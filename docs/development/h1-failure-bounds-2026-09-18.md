## Implemented corrections

- Health aggregation is deterministic: **CRITICAL > WARNING > UNKNOWN > HEALTHY**. An empty aggregate is UNKNOWN; null/failed component results and missing required observations use UNKNOWN with stable reason codes. Unknown inputs no longer disappear when another component is healthy; known warning/critical signals still take precedence. A standalone target can have a healthy Admin API and an UNKNOWN overall result when other components are unobserved; this is not an outage claim.
- Infrastructure, workload and pod checks refuse missing relevant inventory, collection warnings and required malformed/sentinel evidence. Valid observed zero-ready replicas can still be CRITICAL. This does not certify every field in the wider inventory or assessment mapper.
- Management health parses bounded, structured responses from the configured management URL. Empty/malformed/missing status, HTTP denials and unsupported responses remain UNKNOWN. Valid HTTP 503/DOWN remains CRITICAL; contradictory 503/UP or WARNING is UNKNOWN. Nested checks are aggregated without requiring a particular database/cluster check name. Public details contain fixed paths, HTTP statuses, counts and bounded status summaries, not raw bodies, check names/data, URLs or exception text.
- Shared HTTP body subscriber caps actual received bytes, including chunked/misreported-length responses, and cancels on overflow or body deadline. Management health is limited to **64 KiB**, 100 nested checks and JSON depth 16; Prometheus to **1 MiB**, depth 32 and bounded labels. Both reject redirects and configured URLs containing credentials/query/fragment. These are per-response controls, not a single deadline for a multi-query operation. Configured TLS validation behavior is not broadened.
- Prometheus parsing rejects invalid envelopes, duplicates, trailing data, wrong result types, warnings/partial results and invalid sample structure. Instant queries require vectors, range queries matrices. All-nonfinite samples are unavailable, not zero. Actual per-series range sample count is checked; failed ranges do not make another instant query or manufacture a window average/maximum from one sample. `RangeMetricSummary.fromInstant` now returns unavailable temporal statistics.
- Invalid assessment-profile failures use a fixed public message; selected evidence/metrics collector logs omit raw exception text and causes. Generic Java-rule NOT_EVALUATED/SKIPPED results no longer increase evaluated/matched counts. Existing production YAML-rule accounting was already separate; arbitrary custom-rule exception recovery was not redesigned.
